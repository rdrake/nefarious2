# Config / persisted-record fuzzing: findings

Campaign on branch `fuzz/config-records` (base `ircv3.2-upgrade` @ `ca213aa`),
clang 18, libFuzzer + ASan + UBSan.  Harnesses, build and run scripts are in
this directory (see "Harnesses" below).  Every finding was confirmed with the
plain ASan build (`build.sh asan`, `-O0`, no libFuzzer, known-finding masks
off) unless noted; reproducers are in `repro/` and inline below.

Reproduce any of them with:

```sh
fuzz/config/build.sh asan
ASAN_OPTIONS=detect_leaks=0:handle_abort=1 ~/fz/out-asan/fuzz_conf    fuzz/config/repro/F7-crule-or-uninit-free.conf
ASAN_OPTIONS=detect_leaks=0:handle_abort=1 ~/fz/out-asan/fuzz_bouncer fuzz/config/repro/F2-bouncer-empty-nick.bin
```

`handle_abort=1` matters: most of the crashes are the ircd's own `assert()`s,
which ASan only symbolizes when it handles SIGABRT.  The `.bin` reproducers
are bouncer records (14 KB, mostly zeros); they are given below as
`base64(gzip -9n file)` and regenerated by
`gen_bouncer_seeds OUT RECORDS_OUT fuzz/config/repro`.

## Summary

| ID | Severity | Where | What | Reach |
|----|----------|-------|------|-------|
| F7 | Medium | `ircd/crule.c:481`, `:542` | `crule_parse` frees an uninitialised child pointer after a syntax error in a `CRule` | conf / REHASH / gitsync |
| F3 | Medium | `ircd/dnsbl.c:112` | infinite loop parsing a DNSBL `host` (index) list with any non-digit character | conf / REHASH / gitsync |
| F8 | Medium | `ircd/ircd_lexer.l:354`, `ircd_parser.y:2072` | `include` has no cycle detection: k self-includes are parsed ~k^10 times | conf / REHASH / gitsync |
| F6 | Low-Med | `ircd/ircd_parser.y:366-377` | conf arithmetic: division by zero (SIGFPE) and signed overflow | conf / REHASH / gitsync |
| F10 | Medium (data loss) | `include/bouncer_session.h:438` | frozen v8 record layout is not frozen; every real v8 session is dropped and then deleted | boot, DB from a v8 build |
| F2 | Low-Med | `ircd/bouncer_session.c:3103` | empty `bsr_nick` restores a nameless ghost; its exit asserts (`ircd_snprintf.c:2059`) | boot, corrupt/foreign record |
| F5 | Low | `ircd/bouncer_session.c:3114`, `:3591` | v12 record used in place: unterminated `bsr_kc_id` read past the record | boot, corrupt/torn record |
| F9 | Low (hardening) | `ircd/bouncer_session.c:3082-3206` | restored identity strings are not validated (CR/LF, spaces, duplicates) and are burst verbatim | boot, corrupt/foreign record |
| F1 | Low | `ircd/bouncer_session.c:3320`, `:3479`, `:3529`, `:3728` | struct overlays on RocksDB value buffers that are not aligned | boot, every record |
| F4 | Low | `ircd/s_auth.c:2017-2026` | `fork()` failure in `auth_spawn` leaves deleted sockets with live fds; next REHASH deletes/closes them again | REHASH under fork failure |

Severity is for this codebase's threat model: the conf is trusted admin
input, but it is re-read at REHASH and `linesync`/`gitsync` fetch conf
fragments from a remote git repository, so a malformed conf there is a
remote DoS of every server that pulls it (a crash, or a hang that freezes
the event loop and drops every client and link).  Persisted bouncer records
are read once at boot; they matter when the DB holds a record from an older
or newer build, a torn write, or was edited.  None of these is reachable
from an IRC client or a peer server directly.

## F7 — `crule_parse` frees an uninitialised pointer (CRule syntax error)

**Severity:** Medium.  Crash (SEGV / invalid free / heap corruption) while
parsing the conf; at REHASH that takes the server down.

**Reproducer** (`repro/F7-crule-or-uninit-free.conf`; the `&&` variant is
`repro/F7-crule-and-uninit-free.conf` with rule `connected(a) && |&`):

```
General { name = "fuzz.example.net"; description = "fuzz"; numeric = 1; };
CRule { server = "*"; rule = "connected(a) || &|"; };
```

base64: `R2VuZXJhbCB7IG5hbWUgPSAiZnV6ei5leGFtcGxlLm5ldCI7IGRlc2NyaXB0aW9uID0gImZ1enoiOyBudW1lcmljID0gMTsgfTsKQ1J1bGUgeyBzZXJ2ZXIgPSAiKiI7IHJ1bGUgPSAiY29ubmVjdGVkKGEpIHx8ICZ8IjsgfTsK`

**Stack** (plain ASan):

```
ERROR: AddressSanitizer: SEGV on unknown address
    #0 crule_free           ircd/crule.c:767:18
    #1 crule_free           ircd/crule.c:777:7
    #2 crule_parse          ircd/crule.c:454:5
    #3 yyparse              ircd/ircd_parser.y:1458:20
    #4 read_configuration_file ircd/s_conf.c:1277:3
    #5 rehash               ircd/s_conf.c:1416:3
```

**Root cause.** `crule_parseorexpr()` allocates the `||` node with
`MyMalloc()` (crule.c:481, not zeroed) and sets only `funcptr`, `numargs`,
`arg[0]` and `arg[2]`; `arg[1]` is filled in by the *next* loop iteration.
When the token after `||` does not lex (`crule_gettoken()` returns
`CR_UNKNWTOK`, e.g. for `&|`, a lone `&`, or a byte that cannot start a
word), the function returns at crule.c:518 with `arg[1]` uninitialised.
`crule_parse()` then calls `crule_free(&ruleroot)` (crule.c:454), which for
an and/or node recurses into `arg[1]` whenever it is non-NULL
(crule.c:776-777) and dereferences the garbage pointer (crule.c:767).
`crule_parseandexpr()` has the same shape for `&&` (allocation at 542,
early return at 579).  The "so free doesn't seg fault" assignments at
crule.c:508/569 cover only the missing-operand case, not the lexer-error
return; the `!` node (crule.c:620-626) does initialise its `arg[0]`.  This
is inherited ircu code.

**Fix.** Allocate the node zeroed (`MyCalloc(1, sizeof(struct CRuleNode))`)
in both `crule_parseorexpr` and `crule_parseandexpr` (and
`crule_parsefunction` for symmetry), or set `arg[1] = NULL` right after
allocation.

**Found by:** `fuzz_conf` after ~10 minutes (the shipped `CRule` example
with one byte flipped).  The conf campaign then ran with
`malloc_fill_byte=0` to get past it.

## F3 — DNSBL index list with a non-digit hangs the server

**Severity:** Medium.  Infinite loop inside `yyparse`: at boot the server
never starts; at REHASH (or a gitsync pull) the event loop stops for good.

**Reproducer** (`repro/F3-dnsbl-index-hang.conf`):

```
General { name = "fuzz.example.net"; description = "fuzz"; numeric = 1; };
DNSBL { name = "dnsbl.example.org"; host = "127.0.0.2"; };
```

base64: `R2VuZXJhbCB7IG5hbWUgPSAiZnV6ei5leGFtcGxlLm5ldCI7IGRlc2NyaXB0aW9uID0gImZ1enoiOyBudW1lcmljID0gMTsgfTsKRE5TQkwgeyBuYW1lID0gImRuc2JsLmV4YW1wbGUub3JnIjsgaG9zdCA9ICIxMjcuMC4wLjIiOyB9Owo=`

The plain ASan build is killed by `timeout 30` (rc 124).  Stack when
interrupted:

```
#1 dnsbl_parse_index (index=...) at ircd/dnsbl.c:120
#2 dnsbl_add_server (domain="dnsbl.example.org", ...) at ircd/dnsbl.c
#3 yyparse () at ircd/ircd_parser.y:2020
#4 read_configuration_file () at ircd/s_conf.c:1277
#5 rehash (cptr=..., sig=2) at ircd/s_conf.c:1416
```

**Root cause.** `dnsbl_parse_index()` (dnsbl.c:112-122) skips spaces and
commas, then calls `strtol(p, &endp, 10)` and sets `p = endp`.  For any
other character (`.`, `;`, `/`, a letter, `-x`) `strtol` consumes nothing,
`endp == p`, and the `while (*p)` loop spins forever.  A natural typo
triggers it: `host = "127.0.0.2";` (the reply address instead of the index
number), `host = "2;3"`, `host = "2 3x"`.  The parser keyword for this field
is `host`, which makes the address mistake likely.

**Fix.** Advance at least one character when nothing was parsed, and reject
the block with a CONFIG error:

```c
val = strtol(p, &endp, 10);
if (endp == p) {            /* not a number: report and skip it */
  log_write(LS_CONFIG, L_ERROR, 0, "DNSBL index: bad character '%c'", *p);
  p++;
  continue;
}
```

Also note `mask |= (1 << val)` with `val == 31` shifts into the sign bit of
an `int` (UB); use `1u << val`.

## F8 — `include` cycles: exponential parse time

**Severity:** Medium (DoS).  A conf that includes itself a few times hangs
the parser for minutes to hours.

**Reproducer** (`repro/F8-include-cycle.conf`, the conf file is `ircd.conf`
in the working directory, as in a normal install):

```
General { name = "fuzz.example.net"; description = "fuzz"; numeric = 1; };
include "ircd.conf";
include "ircd.conf";
include "ircd.conf";
include "ircd.conf";
```

base64: `R2VuZXJhbCB7IG5hbWUgPSAiZnV6ei5leGFtcGxlLm5ldCI7IGRlc2NyaXB0aW9uID0gImZ1enoiOyBudW1lcmljID0gMTsgfTsKaW5jbHVkZSAiaXJjZC5jb25mIjsKaW5jbHVkZSAiaXJjZC5jb25mIjsKaW5jbHVkZSAiaXJjZC5jb25mIjsKaW5jbHVkZSAiaXJjZC5jb25mIjsK`

Measured parse time for k self-includes (fuzz build, -O1 + ASan): k=1
0.16 s, k=2 0.48 s, k=3 14 s; k=4 took 98 s in the -O0 ASan build.  Each
nesting level multiplies the work by k, down to the depth limit of 10, so
the number of file parses is about k^10 (k=5: ~10^7, k=6: ~6*10^7).  Each
level-10 include also logs "Includes nested too deeply" through
`yyerror()`, which notices every oper.

**Root cause.** `init_lexer_file()` (ircd_lexer.l:354-385) only enforces
`MAX_INCLUDE_DEPTH` (10); it does not remember which files are already on
the include stack, so a cycle is expanded to the full depth at every
`include` statement.  (Also, the `include` action at ircd_parser.y:2072-2075
never frees the `QSTRING` `$2`, a small leak per include per REHASH.)

**Fix.** Refuse to include a file that is already on the include stack
(compare `realpath()`s, or `st_dev`/`st_ino` from `fstat()` of the open
file) with a CONFIG error, and free `$2` after `init_lexer_file()`.
Optionally cap the total number of includes per read.

## F6 — conf arithmetic: division by zero and signed overflow

**Severity:** Low-Medium.  `x/0` is a SIGFPE (server crash) at boot or
REHASH; the overflow is UB that in practice wraps to a negative or tiny
value (`pingfreq`, `sendq`, `maxlinks`...).

**Reproducers** (`repro/F6-expr-divzero.conf`, `repro/F6-expr-overflow.conf`):

```
General { name = "fuzz.example.net"; description = "fuzz"; numeric = 1; };
Class { name = "x"; pingfreq = 1/0; };
```

base64: `R2VuZXJhbCB7IG5hbWUgPSAiZnV6ei5leGFtcGxlLm5ldCI7IGRlc2NyaXB0aW9uID0gImZ1enoiOyBudW1lcmljID0gMTsgfTsKQ2xhc3MgeyBuYW1lID0gIngiOyBwaW5nZnJlcSA9IDEvMDsgfTsK`

```
General { name = "fuzz.example.net"; description = "fuzz"; numeric = 1; };
Class { name = "x"; pingfreq = 65536*65536; };
```

base64: `R2VuZXJhbCB7IG5hbWUgPSAiZnV6ei5leGFtcGxlLm5ldCI7IGRlc2NyaXB0aW9uID0gImZ1enoiOyBudW1lcmljID0gMTsgfTsKQ2xhc3MgeyBuYW1lID0gIngiOyBwaW5nZnJlcSA9IDY1NTM2KjY1NTM2OyB9Owo=`

```
ircd_parser.y:376:34: runtime error: division by zero
ircd_parser.y:373:34: runtime error: signed integer overflow: 65536 * 65536 cannot be represented in type 'int'
```

**Root cause.** The `expr` rules (ircd_parser.y:366-377) compute `$1 + $3`,
`$1 - $3`, `$1 * $3`, `$1 / $3` on `int` with no checks; `NUMBER` is
`strtoul()` truncated to `int` by the lexer (ircd_lexer.l), and
`factoredtime`/`sizespec` multiply again (`$1 * $2`, `* 1024`).  Inherited
from ircd-hybrid via ircu.

**Fix.** Do the arithmetic in `int64_t` (or with `__builtin_*_overflow`),
call `yyerror("division by zero")` and yield 0 for a zero divisor, and
clamp/err on results outside `int`.

## F10 — the "frozen" v8 record layout is not frozen: v8 sessions are lost

**Severity:** Medium (silent data loss on upgrade; no crash).  Every bouncer
session persisted by a v8 build is skipped at the first boot of a newer
build, and deleted from the store if anything else expired or migrated in
the same boot.

**Reproducer** (`repro/F10-bouncer-v8-as-written.bin`: one live v8 record
in the layout v8 builds wrote, plus one expired v12 record):

base64 (gzip): `H4sIAAAAAAAC/+3b3UrCYBzH8ZUFHUh03FEgBJ0MXS9mZ1tESVSkdFBnj3M6crqhCzoK76Ab6Lj7CLqAuoVuowPb2iwxzZciU78fePiPPQ//PRtj7OS3IEmS0HVXaqGe53bze4V9M315aB1VTpzTatY9k75w7VI8oaxvbG4lt1Mip+eNgjQQSziu7XSfV7WeLer1g5JfX57T7/UxrPdhXVoM1kW8MeeNomnX3O7tbq5qRjU49BfKxrUoO5Yh29Wi9AP+E5b91rWPjhXDHa5XxhDWyrEoG4Ndvu3Uw+1OqdPSREqR47IiJ/tq/JvPaG35u9nZke8vcBe+V+OyLwAYV5GwxnRTVCbknma8EX36/F53+omK2a7Z/BOZBquWrQuL9x0AAAAAAAAAAAAAAAAAAADA/9fM66iaqqph8G3eG69hrsc/r/UTiOuhoWUzjagUZMKUlgn1YvxCf019hf6Uru0mN/TXds+E/oZD6A8A/gahv+lA6A8AAAAAAAAAAAAAAAAAAAAAMApvcdMiG01xAAA=`

```
$ FUZZ_VERBOSE=1 out-asan/fuzz_bouncer repro/F10-bouncer-v8-as-written.bin
fuzz_bouncer: 2 record(s), restored 0, 0 left in the store
```

(The generator's v8 *seed*, built with the header's `struct
BounceSessionRecord_v8`, restores fine: `restored 1`.)

**Root cause.** v8 records were written by the builds from fa81e2f (DB
version 8) until 5a1ce20 (version 9), when
`BOUNCER_MAX_ALIASES` was 4 (`git show fa81e2f:include/bouncer_session.h`).
4ad2cd8 raised `BOUNCER_MAX_ALIASES` to 16 and correctly froze the v9
struct's array as `bsr_aliases[4]`, but `struct BounceSessionRecord_v8`
(include/bouncer_session.h:397-439) still declares
`bsr_aliases[BOUNCER_MAX_ALIASES]` (line 438).  Its size went from 14320
to 14608 bytes, so `bounce_db_restore()`'s check
`vlen != sizeof(struct BounceSessionRecord_v8)` (bouncer_session.c:3417)
rejects every real v8 record and `continue`s silently.  The cleanup pass
then classifies it as "Unknown version or wrong size — evict"
(bouncer_session.c:3732) and deletes it whenever `expired > 0 ||
migrated_v7 > 0`.  The other frozen layouts (v7, v9, v10, v11) match what
their builds wrote (checked against 063d2c2, 5a1ce20, 4ad2cd8, 512812e);
v7, v8 and v9 still use the live `BOUNCER_MAX_CHANNELS` /
`BOUNCER_MAX_CONN_HISTORY` macros, so the same bug recurs the day either
changes.

**Fix.** Declare `bsr_aliases[4]` in `struct BounceSessionRecord_v8`, and
replace every macro in the `_v7`/`_v8`/`_v9` structs with the literal it had
(`bsr_history[10]`, `bsr_channels[50]`), as v10/v11 already do.  Add
`_Static_assert(sizeof(struct BounceSessionRecord_v8) == 14320, ...)` (and
one per frozen version) so a macro change cannot silently move them again.
Consider logging, not just skipping, a record whose size does not match its
version, and not evicting it.

**Severity:** Low-Medium.  A record with an empty `bsr_nick` is restored as
a registered user with an empty name.  When the hold ends (expiry,
`bounce_hold_expire` → `exit_client`) the QUIT to its channels asserts and
aborts the server (asserts are compiled in: `--enable-debug`, no
`--disable-asserts`).  Without asserts, the empty nick is hashed, burst to
peers in `N` and sent in QUITs.

**Reproducer** (`repro/F2-bouncer-empty-nick.bin`, a valid unexpired v12
record with `bsr_nick` zeroed):

**Stack** (plain ASan, harness teardown = the no-alias branch of
`bounce_hold_expire`):

```
    #5 doprintf                 ircd/ircd_snprintf.c:2059:4   assert(0 != *(cli_name(cptr)))
    #6 ircd_vsnprintf           ircd/ircd_snprintf.c:2164:3
```

## F5 — v12 records are used in place: unterminated `bsr_kc_id` over-read

**Severity:** Low (read of a few bytes past the record; no write).

**Reproducer** (`repro/F5-bouncer-kcid-overread.bin`, a v12 record whose
last field and the struct's tail padding are all `'A'`):

base64 (gzip): `H4sIAAAAAAAC/+3WTUrDQBTA8dG6LOLalVAQ3IQ2ftS6iyJaREXFhctpOm0waRLSEVxJb9ALuPYeggfQK3gSExM/0EatH0j1/4PHC5nHm8kwhCkKIaRta/GMddRYa663Npz68Za37e+Ge9GBPhSv6MAtV8z5hcWl6nJNNuymaomheDLUQZg/bq2+26LX23STfHtTv89XWb7I8tRkWleIYyKOthN0dX67s5OuitLHpNBQp7ITesoIorb4gmSHjaR197Gjr/Tneu0r6c3syI4abvoXry77K+6g0krNNMqGaVQ/1Pg792hu+q3R8V9fX+o8O1ejsi4AGFWFLJdsR/p/5JvG4iheP/2vB12iSoF2Hm4i/8GsF9jS47wDAAAAAAAAAAAAAAAAAAAAAH6GleMOtEG0rlg5AAA=`

```
ERROR: AddressSanitizer: heap-buffer-overflow ... READ of size 1
    #0 account_id_valid        ircd/account_id.c:64:15
    #1 bounce_create_ghost     ircd/bouncer_session.c:3114:7
    #2 bounce_db_restore       ircd/bouncer_session.c:3536:13
0x... is located 0 bytes after 14680-byte region
```

(The harness hands the restore an exact-size heap copy of each RocksDB
value; in the server the read continues into RocksDB's block buffer.)

**Root cause.** For the current version `bounce_db_restore()` points `rec`
straight at the stored bytes (bouncer_session.c:3320) instead of copying
into `rec_buf` as the migration branches do, so no string field is
guaranteed NUL-terminated.  Most uses are bounded `ircd_strncpy()`s, but
`account_id_valid(rec->bsr_kc_id)` (3114, 3591) runs to the first NUL, and
`bsr_kc_id` is the last field.  `bounce_restore_channels()`'s
`get_channel(..., rec->bsr_channels[i].name, ...)` and the
`strcmp(rec->bsr_aliases[i].bsar_server, me_yxx)` loop also read
unterminated fields (they stop inside the record only by luck of the
following fields).

**Fix.** Copy the v12 record into `rec_buf` like the other branches and
force-terminate every `char[]` field (one helper, used by all versions),
e.g. `rec_buf.bsr_kc_id[sizeof(rec_buf.bsr_kc_id) - 1] = '\0'`.  That also
fixes F1.

## F9 — restored identity strings are trusted (hardening)

**Severity:** Low.  Needs a corrupted or tampered DB, but then it is P10
line injection toward every peer.

**Reproducer** (`repro/F9-bouncer-unvalidated-identity.bin`: two v12
records, both with nick `"x y\r\nAB SQ hub :pwn"`, one with channel
`"#a b,0"`):

base64 (gzip): `H4sIAAAAAAAC/+3b30rCUBzA8ZVdhUXXXQ2EIIih64/pnUaURIVKF3V3Nmcj5zZ0kt2Eb9ALdN17BD1AvUIvYtpWWdkfLRT1+4HDb5wzfjs7O4xz8wtLkiR03ZM6pI61rcJ2ccfMnO1Z+/ahm63kvSPpE88pRWPq6tr6RnwzITS9YBSlnljC9Rz36/FU+scUjcZuqR0fHzLP8S6IN0FcmPfvC7XaTKvV5Yu52VRazmdls6bJSffc7kx3WasaFf/SdKqeYtRF2bUMxamcSn/QXmGlnbr6mtE2vP5y5QxhyQeibPT2+A9dt1fJUrdbYwlViSqqEv9V4v9co+XF70anhz4/33Wwr0ZlXgAwqkJBjOimsMfknaZaLXz/9r/udoiKCFlbiU7Od16yHF1Y7HcAAAAAAAAAAAAAAAAAAAAAwGA10/lcMyz5tXdqx0DqhOLKsSuuVN93UVzZH4orAWAwJra40vHMl5PIJKC4EgAAAAAAAAAAAAAAAAAAAAAwDE8dCozktXIAAA==`

```
fuzz_bouncer: 2 record(s), restored 2
```

Both are restored with no complaint: two local clients with the same nick
in the client hash, and a nick holding a space and CR LF.  At the next
burst `s_serv.c:424-430` sends `N` with `cli_name`, `username`, `realhost`
and `cli_info` formatted verbatim, so the CR LF splits the line and the
remainder (`AB SQ hub :pwn`) reaches the peer as a separate P10 command
from this server.  `bounce_db_restore()`'s comment "no collision possible"
covers live clients, not two records in the DB.

**Fix.** Before `bounce_create_ghost()`: require `do_nick_name()` (or the
same character/length rules) for the nick, `valid_username`-style rules for
user/host, no control characters in realname/host fields, a valid channel
name for each channel (`IsChannelName` + no space/comma/BEL), and
`!FindClient(nick)`; skip and log records that fail.

## F1 — struct overlays on unaligned RocksDB values

**Severity:** Low (UB; harmless on x86 today, can fault on strict-alignment
targets or with vectorised loads).

**Reproducer:** any valid record, e.g. `seed-000` (v7) or `seed-005` (v12)
from `gen_bouncer_seeds`, with the alignment check on and the value placed
off alignment as RocksDB does:

```sh
KEEP_ALIGN=1 fuzz/config/build.sh asan ~/fz-align
FUZZ_VALUE_OFFSET=4 ~/fz-align/out-asan/fuzz_bouncer seed-000
```

**Root cause.** `bounce_db_restore()` casts `db_iter_value()`'s pointer to

union of the frozen structs) before reading any field, as the v10/v11
branches and `presence_init()` already do.

## F4 — `auth_spawn` fork failure: double socket delete at next REHASH

**Severity:** Low.  Needs `fork()` to fail (RLIMIT_NPROC, ENOMEM on a
large process).  With asserts the next REHASH aborts; without them it
`close()`s two fds that may by then belong to other connections.

**Reproducer:** `repro/F4-iauth-fork-fail.conf` with `fork()` failing (the
`asan` build's `fork()` stub returns EAGAIN), then any REHASH.

```
General { name = "fuzz.example.net"; description = "fuzz"; numeric = 1; };
IAuth { program = "/bin/true"; };
```

base64: `R2VuZXJhbCB7IG5hbWUgPSAiZnV6ei5leGFtcGxlLm5ldCI7IGRlc2NyaXB0aW9uID0gImZ1enoiOyBudW1lcmljID0gMTsgfTsKSUF1dGggeyBwcm9ncmFtID0gIi9iaW4vdHJ1ZSI7IH07Cg==`

```
ERROR: AddressSanitizer: ABRT
    #5 socket_del          ircd/ircd_events.c:738:3   assert(!(sock->s_header.gh_flags & GEN_DESTROY))
    #6 iauth_disconnect    ircd/s_auth.c:2161:5
    #7 auth_close_unused   ircd/s_auth.c:2198:5
    #8 rehash              ircd/s_conf.c:1428:3
```

**Root cause.** On `fork()` failure `auth_spawn()` (s_auth.c:2017-2026)
`socket_del()`s and `close()`s both IAuth socket pairs but leaves
`s_fd(i_socket(iauth))` and `s_fd(i_stderr(iauth))` set and keeps the
`iauth` around.  The next REHASH marks it closing and `iauth_disconnect()`
(s_auth.c:2157-2168) sees `s_fd != -1`, `close()`s the stale fd numbers
again and calls `socket_del()` a second time.

**Fix.** Set `s_fd(...) = -1` after each `socket_del()`/`close()` in the
error paths of `auth_spawn()` (and its earlier `socket_add` failure path).

## Harness artifacts (discarded)

All of these came from the harness, not the ircd, and were fixed in the
harness:

* 31 `free_client` "`cli_hnext(cptr) == cptr`" aborts: the F2 mask renamed
  the nameless ghost without re-hashing it.  Fixed by `hRemClient`/
  `hAddClient` around the rename.
* heap-use-after-free in `__wrap_db_iter_value`: one shared value copy was
  freed when ghost creation read metadata through a nested iterator while
  the restore still held its record.  Copies are per-iterator now.
* every `-fork` job reported as a crash: `SIGCHLD` was set to `SIG_IGN` in
  `LLVMFuzzerInitialize`, which also runs in the fork-mode parent, so its
  `waitpid()` on jobs failed.
* "write conf: No space left on device": fuzzed `Features { "LOG" ... }`
  blocks writing DEBUG logs into the sandbox, plus one RocksDB dir per job.
  Sandbox files are truncated after each input and removed at exit.

## Masks used to keep fuzzing past known findings

The `fuzz` build masks F3, F5, F6, F7, F8 and the F2 teardown so the
campaign does not stop on them; `-DFUZZ_UNMASK_KNOWN` (always on in the
`asan` build) removes the masks:

| Finding | Mask |
|---------|------|
| F3 | `--wrap=dnsbl_add_server` drops non-index characters |
| F5 | value copies get one trailing NUL |
| F6 | `/` outside strings/comments becomes `+`; `y.tab.c` built without `-fsanitize=signed-integer-overflow` |
| F7 | conf campaign runs with `ASAN_OPTIONS=malloc_fill_byte=0` |
| F8 | `--wrap=init_lexer_file` caps include depth at 2 |
| F2 | teardown renames (and re-hashes) a nameless ghost |
| F1 | `-fno-sanitize=alignment` (`KEEP_ALIGN=1` turns it back on) |

## Harnesses

| Target | Input | Drives |
|--------|-------|--------|
| `fuzz_conf` | conf texts split by `\n#@REHASH@\n` (≤3) | `rehash(&me, 2)` per piece: lexer, parser, `s_conf.c`, features, classes, listeners, SASL/Keycloak/Webhook/AuthToken, DNSBL, CRule, IAuth; a socketless client holds conf/class/listener refs across the reload; baseline conf reloaded after |

| `fuzz_bouncer` | ≤4 raw values split by `\xffBSR\xff` | values in the metadata RocksDB `bouncer_sessions` CF, `bounce_db_restore()` (v7..v12 dispatch, migrations, ghosts, channels, aliases, oper grant, metadata load), sessions torn down like a hold expiry |

executed); `include` of a non-regular file (fifo, `/dev/stdin`) is refused.
